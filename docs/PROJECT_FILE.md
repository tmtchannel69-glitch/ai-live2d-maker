# 作業ファイルの保存・再開

## 保存とデータの扱い
オーナーの「続けて」を承認として、端末ファイルへの保存・読み込みを実装。外部サービスを追加せず、既存の fflate を使う。元画像を含むため、素材 PNG の ZIP とは分けて `ai-live2d-work.zip` をダウンロードする。

保存・読み込みはブラウザ内。自動保存、ブラウザの永続領域、サーバーへの画像保存、クラウド同期は今回の対象外。ZIP は暗号化していない。作業を開く操作で現在の画面内の状態を置き換えるため、必要な作業は先に保存する。ファイルが不正な場合は置き換えない。

点指定・ブラシの取り消し履歴、ブラシ画面で未反映の下書きは含まない。反映済みの補正 PNG を保存する。指定を変更していても、結果を生成したときの指定を別に持つことで「以前の結果」の表示を復元する。読み込みだけでは AI 処理を開始しない。

## 版 1 の構造
再圧縮しない ZIP（保存方式 0）。このアプリの作業 ZIP 専用で、一般の ZIP や素材 ZIP の取り込みではない。

| 項目 | 内容 |
|---|---|
| project.json | format=ai-live2d-maker、version=1、source、mode、selected、prompts、parts |
| source/image | 元画像のバイト列を保持。名前・形式・表示サイズは source に保存 |
| parts/hair.png など | 保存対象の結果。id、ai、manual、generatedPrompt を parts に保存 |

source は name / type / path / width / height。parts は id / path / ai / manual / generatedPrompt。generatedPrompt は結果生成時の指定、prompts は現在の指定。画像名は表示に textContent を使い、保存時にパス文字・制御文字を除き 120 文字までにする。

未完成の状態（結果なし、指定なし、除く点だけ、選択なし）も保存可能。デモは異なる切り出しサイズの PNG を復元し、AI 結果は元画像と同じサイズを要求する。AI 再分離やブラシ補正は復元した結果を基点に続けられる。

## 制限と読み込みの確認
- 作業ファイル全体 100 MiB、元画像 10 MiB、各 PNG 32 MiB、作業情報 64 KiB。各辺 4096 px、1600 万画素以下。
- ZIP の項目名・重複・保存方式・展開サイズを確認してから抽出する。許可したファイルだけを読み、圧縮された項目は版 1 として受け付けない。ディスクに展開しない。
- 情報の版、処理方式、ID、選択の重複、点と枠の有限な正規化座標・点数、パーツの有無、PNG ヘッダー、元画像と出力のサイズを確認。画像を一枚ずつデコードし、確認用の画像データを解放する。
- 検証が完了してから画面に適用する。リセット・別画像の選択後に遅い読み込みや保存処理が完了しても反映・ダウンロードしない。
- 入力の構造・画像として読めることの検証であり、署名や完全な改ざん検出は提供しない。上限内でも大きな画像のメモリ負荷は残る。特に JPEG / WebP の寸法確認はデコード後で、最大サイズでの実機メモリ検証は未実施。

## 検証記録
- ブラウザ合計 20 件（実 SAM 一件含む）、サーバー既存 10 件、本番ビルドを確認。
- 新規四件: 元画像・補正 PNG のバイト一致、点と枠・選択・方式、変更済み指定と結果の区別、再保存、再開後のブラシと一パーツ AI 再分離、未完成の指定、デモを検証。
- 破損 ZIP、未対応の版、画像サイズ不一致、座標範囲外、パーツ欠落・不明 ID、余分な項目、不正 PNG、選択の重複、不正な画像名・プロパティ、未対応の圧縮、ファイルサイズ超過で現在の作業を保持することを確認。
- 遅い読み込みの途中リセット、保存時の読み取り失敗、途中リセット後の不要なダウンロード抑止を確認。アップロード完了を待たずに検証対象の URL を取得したテストの不具合を修正して再実行。
- 実 SAM による自作画像の PNG を作業ファイルへ保存し、ページ更新後の復元でサイズ 256×384 と透明度を比較。
- 提供 JPEG と既存の実 SAM 髪マスクでも保存・復元を確認。元画像とマスクのバイト一致、復元サイズ 853×1280 を確認。API は過去のマスクで代替し、この確認では AI を再実行しない。画像と作業 ZIP は /tmp のみで GitHub へ含めない。
- スマホ幅 Chromium と既存デスクトップテストで確認。実機 iPhone / Android / Safari、新規 Windows、手動ファイルの端末間移動は未検証。

## 再開と後続
README の起動手順で画面を起動し、「作業ファイルを開く」で端末に保存した ZIP を選ぶ。AI 再分離が必要な場合だけ既存のローカル SAM サーバーも起動する。次の提案は左右の目・髪の前後など制作向け分類への拡張。版 1 の作業ファイルと既存四分類を維持する方針を設計してから、承認後に実装する。

## 制作向け分類を含む版2
制作向け状態がある場合は version=2 とし、template（basic / production）と templates（構成ごとの mode / selected）を追加する。prompts と parts は両方の構成を保存し、結果の方式は属する構成の方式と一致させる。基本四分類だけの場合は版1で書き出し、版1を読み込む場合は制作向け状態なしの基本構成として扱う。

項目名の定義は shared/parts.json。版2の結果は最大19項目（四分類と制作15項目）、作業情報の上限は256 KiB。全体100 MiB、元画像10 MiB、各 PNG32 MiB、画像サイズの上限は維持する。ZIP保存方式0や項目名等の検証も維持。素材ZIPは現在表示中の構成のみ、作業ZIPは両構成を保存する。版2は旧アプリへ読み込めない。

## 確認記録を含む版3
記録がある場合はversion=3で、版2の構成情報にreviewsを追加する。形式はパーツIDをキーとする `{boundary,fill,note}`。boundaryはunchecked / checked / needs_fix、fillはunknown / needed / not_needed、noteは500文字まで。未知のID・フィールド・状態値、不正な型、AI結果のないcheckedを拒否する。指定変更前の確認記録は保存できるが画面では現在の確認済みとして集計しない。

記録なしでは既存の版1・2を書き出す。旧版の読み込み時は記録なし（未確認）として扱う。版3は旧アプリへ読み込めない。ファイルサイズ等の制限は版2と同じ。
