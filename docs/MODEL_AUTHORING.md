# VTube Studio向けモデル制作への拡張

2026-10-09。オーナーの「それもできるように」と、用途「VTube StudioなどのLive2D対応ソフト」を受けた方針。従来の素材準備に加え、アプリ内での動作設定から対応ソフトで使えるモデルの出力を最終目標とする。完成したモデルの自動生成はまだ実現していない。

## 今回実装した範囲

- 選択中のAI結果を元画像上の位置に合成する「04 動きの試作」。基本・制作向け双方に対応し、固定領域のデモは対象外。
- 各パーツの回転支点（元画像の左上0%・右下100%）、重なり順、頭の傾きへの追従、揺れ幅。初期順序はPSDと同じ仮の順序。数値入力でスマートフォン・キーボードから調整できる。
- 頭の傾き±15度、揺れと呼吸の再生・停止。平面画像の回転と縦方向の微小な拡縮で、立体的な顔の向きや物理演算ではない。各パーツの支点で回転するため、支点を揃えないと頭の部品がずれる。
- 支点・順序・追従・揺れ幅を作業ファイル版4へ保存・復元。調整がなければ従来の版を維持。版1〜3も読み込める。版4は以前のアプリでは開けない。
- プレビューの変形と順序はPNG・PSD・素材ZIPには反映しない。元画像と反映済み補正の素材を維持する。試作をCubismへ変換する処理は未実装。
- 目・口を縮めるだけで自然な瞬きや発話が完成したと扱わない。閉じた目、口の内部、隠れた肌・髪などの素材と変形設定が今後必要。

追加のサービスやSDKは使わず、Canvasによるブラウザ内処理。プレビューに新しい画像送信先や費用はない。再生は手動開始、処理・保存中とページが非表示になったときに停止する。端末の「動きを減らす」設定でも自動再生を行わず、ユーザーが再生ボタンを押した場合だけ動く。

## 構造と制限

- `src/motion-state.js`: 独自設定の初期値と厳密な検証。既知IDのみ、支点0〜1・整数順序0〜99・揺れ0〜15度・追従は真偽値。
- `src/motion-panel.js`: 画面と独自描画。将来のメッシュ編集・Cubism再生は別モジュールにする。現設定を標準Live2Dパラメーターと誤認させない。
- 最大640×960以内に縮小した画像をプレビュー用に保持し、入力は一枚ずつ読み込んで元のビットマップを解放。元画像・AIマスクのサイズ一致を確認し、不一致ではプレビューを作らず作業は保持する。
- 選択・構成・マスク・元画像の変更で再生を停止して古い画像を解放。遅いデコードは世代番号で破棄。作業保存・復元や新しい画像では自動再生しない。
- 元画像や各パーツの最初のデコード自体にはメモリ負荷が残る。実機スマートフォンでの速度・メモリ確認は未実施。
- テストは自作図形と代替AI応答を使用し、元PNGのバイト一致、実画素の変化と重なり順、停止、選択変更、設定の復元と不正設定拒否、旧版互換、遅い処理の破棄、サイズ不一致を確認する。実モデルの動作品質・VTube Studioへの読み込みとは別。

公開資料から確認できた出力経路はCubism Editor。Cubismなしでmoc3を作る、公式にサポートされた素材→コンパイルAPIは今回確認できていない。「絶対に不可能」という証明ではないが、未確認の形式の独自生成や拡張子の変更で対応済みと称さない。Cubism未導入でも、このアプリの制作・独自試作は進められる。実際のmoc3出力とVTube Studio実機確認は別の未完了事項。

## 次の開発順と完了条件

1. **素材と動きの設計**: 部品ごとの支点・重なり順の確認を実施。次は目と口の細分化、動いたときの不足一覧、閉じた目などの素材を準備する方法を設計する。隠れ部分のAI生成・外部送信・費用は今回実施しない。
2. **変形編集**: 瞬き・口・顔の向きのためのメッシュと変形キー、親子関係を設計・試作。完成条件は素材の二重表示や欠けを検出でき、保存後に同じ変形を再現できること。独自描画だけをLive2D互換と呼ばない。
3. **本物の出力経路の確定**: 対応可能なCubism連携・生成形式・利用条件を確認。現在の重大な未解決点。Editor併用を必要とする場合は、オーナーへ操作・環境・費用を示して判断を求める。SDK追加だけでmoc3生成が解決すると扱わない。
4. **VTube Studio向け出力と検証**: 有効なmoc3・model3.json・テクスチャ・必要な物理設定を揃え、既定IDに合う動きと読込をWindowsのVTube Studioで確認。完成条件は実モデルの読み込みと、追跡による顔の向き・瞬き・口の動き・髪の揺れを記録して再現できること。

独自プレビューからVTube Studioに直接つながる出力はまだない。上記3が解決するまで、自動モデル化の完成日やCubism不要の達成を確約しない。mainへのマージ・公開・契約・費用・ユーザー画像の外部送信は従来どおり承認が必要。
