## 通常の制作フロー

| 工程 | 人が行う作業 | AI Live2D Maker への示唆 |
|---|---|---|
| 1. 動きの設計 | 瞬き・視線・口・顔の向き・髪揺れなど、必要な動きと範囲を決める | 動きに応じたパーツ一覧が必要。すべての用途に同じ四分類では不足 |
| 2. 作画・レイヤー分け | イラストソフトで髪や目、口、衣装を動く単位に分ける。通常はレイヤー付き PSD などを用意 | 自動切り抜きの後に、左右や前後の細分化とレイヤー順の確認が必要 |
| 3. 描き足し | 前髪の下の額、髪や服の裏に隠れた領域を動く範囲分描き足す | 切り抜きマスクだけでは未知の画素を作れない。補完は別機能として品質確認が必要 |
| 4. Cubism へ取り込み | 素材を配置し、重なり・名前を整理。画像を変形するためのメッシュと、複数パーツをまとめるデフォーマを作る | 元サイズ・位置、パーツ名、描画順を保存。取り込み可能な形式を検証する |
| 5. 動きの設定 | 目の開閉、瞳の移動、口の形、顔や身体の角度などに対応した変形を作る | PNG 出力だけではこの工程は完了しない。初版の素材準備と将来のモデル化を分ける |
| 6. 揺れ・破綻確認 | 髪や服の揺れを設定。各動きの端だけでなく複数の動きを同時に試す | 隙間・重なり・歪みの確認が必要。静止した分離結果だけで完成判定しない |
| 7. 出力・実行環境確認 | Cubism からモデルやテクスチャ等を書き出し、VTube Studio や Web 表示で追跡・動きを調整 | 最終モデルの形式・SDK・スマホ負荷・利用条件を別途確認 |

これは一つの一般的な流れであり、パーツ数や順序は必要な動きと制作者の方法で変わる。

## パーツ分けと作画のコツ（一般的な制作知識）
- 先に動きを決める。細かく分けるほど良いとは限らず、動かさない部分の過分割は管理と変形の負担になる。
- 左右はキャラクター基準で統一し、L/R の名前と画面上の位置を混同しない。
- 髪は前髪・横髪・後ろ髪、必要なら揺らす束単位に分ける。髪飾りは髪と一体で動かすか別に動かすかを決める。
- 目は左右の独立性を確認し、動きに応じて白目・瞳・まぶたやまつ毛・ハイライトを分ける。両目を一枚で抽出できても個別の瞬きや視線の準備が終わったとは言えない。
- 額や肌を先に連続した面として整えると、上の髪や目を動かしたときの穴を避けやすい。口を開くなら口内や歯等も必要に応じて準備する。
- 境界でぴったり切るだけでなく、動くと露出する重なり部分を描く。余白の量は動かす範囲で決め、固定の画素値で保証しない。
- 元のキャンバスと位置を保ち、名前と描画順を整理する。確認表示の透明余白を省いても、素材を勝手に移動しない。
- 黒・白・市松模様など異なる背景で、白い縁、残った背景、穴、半透明の髪を確認する。
- 素材の分離時に元絵の影や色のつながりが途切れていないかを見る。重なりを除いたあとに不自然な影が残る場合は作画修正が必要。

## モデリング後のコツ（資料で確認できた点を含む）
- 公式 Haru サンプルは左目・右目の開閉、視線 X/Y、口の開閉・形、顔や体の角度、呼吸などを別のパラメータとして持つ。全モデルに同じ構成を強制する根拠にはしない。
- VTube Studio は標準のパラメータ ID と範囲の使用を推奨。表示名だけを揃えるのではなく ID を確認する。
- 出力の model3.json はモデルやテクスチャ、物理等への参照を持つ。PNG 一式だけでは動くモデルを読み込めない。
- 物理設定の出力とモデルへの登録を確認する。髪揺れ等が出ない原因を切り抜きだけに求めない。
- VTube Studio は大きなテクスチャがモバイルで遅延やクラッシュにつながる場合があると記載。静止画の解像度と実行時の負荷を別々に評価する。
- 顔追跡の値が動いてもモデルが動かない場合、表情・モーション・物理が値を上書きしている可能性がある。滑らかさを増すと遅れが増える点も確認する。

## 提供画像へ当てはめた提案
- 長い髪は、一括抽出後に必要な前後・左右・束へ分ける工程が必要。黒いリボンとヘアピンをどう動かすかも決める。
- 顔の額部分は前髪の移動で露出するため、現在の前髪形に合わせて切り抜いた肌だけでは不足する。
- 目は左右を独立させる。視線を動かす場合は瞳と白目等の準備まで確認する。
- 黒いトップス、白いジャケット、左右の袖、スカート、ベルト類は一つの body 項目では意図が伝わりにくい。
- まず上半身の小さな動きを目標にした素材セットを試す案。全身の関節動作や衣装の大きな揺れまで一度に保証しない。

## 開発の優先順位を見直す案（未承認・未実装）
1. 「どこを動かすか」から選べるパーツ一覧と命名規則の設計。既存四分類を変更するため仕様承認を得る。
2. 複数の追加・除外点、候補マスクの選択、ブラシ修正で見えている部分を整える。
3. 個々の素材の透明度・位置・重なりを確認し、欠けた部分を明示する。補完済みと誤認させない。
4. 描き足しは当面人が確認できる手順を用意。生成 AI を使う場合は別評価・送信先・費用・利用条件を承認する。
5. レイヤー付き素材出力を検討。PSD 対応は現行 Cubism で読み込みテストを行い、対応を名乗る。現在は PNG ZIP のみ。
6. 所有者が利用を許可したモデルを Cubism で手動制作し、一回の取り込み・動作確認を基準として将来の自動化範囲を決める。

「素材を準備する初版」の目標は維持する。今回の調査を理由に動くモデルの全自動生成へ勝手に範囲を広げない。
