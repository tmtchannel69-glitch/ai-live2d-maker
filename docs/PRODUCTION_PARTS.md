# 制作向けパーツ分類の実装と確認

## 範囲と互換性
オーナーの「続けて」により、設計済みの上半身15項目を実装。shared/parts.json を画面・ファイル検証・サーバーの共通定義とする。UTF-8 を明示して読み込む。モデル・依存関係・チェックポイントは従来どおり。

前髪、横髪左右、後ろ髪、顔の肌、首、目左右、眉左右、口の見える部分、トップス、ジャケット本体、袖左右。本人の左右で、正面では左は画面右。AI は項目名から判定せず、指定された点・枠で領域を選ぶ。目の白目・瞳・まぶた等を個別に準備する機能ではない。

- 制作向けは AI のみ。固定矩形のデモは基本四分類で維持する。
- 構成切り替えで両方の選択・方式・指定・結果を保持。結果を勝手に分割・改名しない。
- 方式変更は現在の構成だけ結果を消し、元画像の再選択・リセットは全指定・結果を消す。
- 素材ZIPは表示中の構成。作業ZIPは両構成を保存。版1を基本構成として読み込み、基本のみの状態は版1保存を維持。制作状態を含む場合は版2。旧アプリは版2に非対応。
- サーバーは従来の一回4パーツまでを維持。画面から15パーツ選択した場合は4 / 4 / 4 / 3 の順次リクエスト。途中失敗時は画面の更新を行わず旧結果を保持し、再実行は先頭から。リセットで後続を止め、処理中のサーバー計算自体は完了まで続く。
- 作業ファイル全体100 MiB、元画像10 MiB、各PNG32 MiB、画像4096 px / 1600万画素は維持。版2の作業情報は256 KiBまで。大量パーツ・大きな画像の端末メモリは引き続き未検証。

## 操作の検証
ブラウザ23件（実SAM一件を含む）、サーバー11件、本番ビルド成功。新規ブラウザ三件で構成切り替え、左右と座標、ブラシ補正、単体再分離、素材ZIPの対象、両構成の版2保存・復元、版1読み込み、15項目のバッチ、途中失敗・リセット、不正な版2の保持、スマホ幅とPC幅を確認した。新規三件は代替API。

実SAMの既存テストで従来hairと新規eye_lを自作図形で推論し、両構成の結果保持と版2の保存・復元を確認。新IDでモデルの処理が通ることの確認であり、自作図形を実際の目として正しく判定したという評価ではない。

サーバーの新規一件では共通定義の制作15 IDを分けて処理し、ID・PNG名を保つこと、5個一度の要求を拒否することを確認。代替マスクを使用。select の option に対する自動テストの判定方法を DOM の disabled プロパティ確認に修正し、対象を再実行した。

実機 iPhone / Android / Safari、新規Windowsは未検証。確認状態・描き足し状態の記録、PSD、生成補完、動くLive2Dモデルは未実装。
