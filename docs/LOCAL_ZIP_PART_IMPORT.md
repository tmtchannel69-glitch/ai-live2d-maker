# ローカルZIP一括取り込み（iPhone向け・オフライン）

2026-10-25。これまでの「個別の透過PNGを最大33枚選ぶ」操作に加え、既存のキャラクターZIPや同等構成のZIPを1つ選択できる取り込み経路を試作。

## 操作

1. キャラクター生成モードで「デザイン指定の端末内描画」を選び、33パーツの基準キャラクターを作成する。
2. 「透過PNGをまとめて取り込む（試験版）」から、従来の複数PNGファイルか「ZIPファイルを1つ選択」を選ぶ。
3. ZIP内の役割別PNG（`parts/iris_l.png` / `iris_l.png` など）を端末内で検査。ZIP以外へファイルを送信しない。
4. 役割の不足数を確認し、「選択したパーツをまとめて取り込む」を実行。既存のPNG透過・寸法・画素配置・モデル生成検証をすべて再利用。
5. 比較プレビューと品質警告を確認して実験用ZIPを保存する。通常の元キャラクターは変更しない。

## 受け入れ制限

- ZIP自体は16 MiB以下、エントリ最大64個、取り込み対象は役割名と完全一致するPNGだけ（最大33枚）。
- 画像1枚8 MiB以下、展開後のPNG合計12 MiB以下。展開前にZIPの記載サイズと重複をチェックする。
- `parts/` の直下またはZIPのルートにある `role.png` だけを認める。
- トラバーサル（`../`）、フォルダの深いネスト、知らないファイル、重複した役割、未対応の圧縮方式、構造不正は拒否。
- キャラクター生成ZIPに含まれる既知のREADME/JSON/INP/INX等は解凍せず無視。これらの記述から「AI生成済み」等の表示を決めない。
- ZIP内に1枚でも不正なPNGがある場合、全件置換を中止し、既存モデルは保持する。
- ZIPの内容を追加APIへ送信しない。AI推論・課金・ログイン・mainへの統合は実行しない。

## テスト

- 既存のキャラクターZIPをアップロードし、33枚の対応PNGを取り込んでInochi2D INP/INXモデルを1回生成し、保存元の通常ZIPが変わらないことを検証。
- `../iris_l.png` の危険なパスと、ルートと`parts/`に同一役割が重複するZIPを拒否するテスト。
- 従来の個別PNG選択、33枚全件置換、品質警告、透過、Inochi2D関連、PSD保存の回帰テストを維持。

テスト用の図形と既存基準パーツはAI画像ではない。33PNGがZIPで読めても、画像1枚から33PNGへの全自動分離、隠れ領域の復元、自然な動作、Live2D Cubism/VTube Studio互換を保証しない。GitHub Actionsの実際の完了結果が出るまで合格とは表記しない。
