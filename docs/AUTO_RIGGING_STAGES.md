# 自動リギングの段階と判定

2026-10-23。`feature/detailed-character-parts`のe89bcf0を基準に、オーナー指定の順序で進める。通常5役割と既存品質版の生成器/API/UIは維持し、共通パーツ形式からの独立した出力を拡張する。

## 参考資料と利用できる機能

指定の[「Palmie 363」公開紹介](https://www.palmie.jp/courses/363/lp)は、この環境では接続403で本文未取得。講座の手順を確認したとはしない。有料本文・動画・PSD・サンプルモデルは要求していない。

前段で本文を確認した[Live2D公式の素材分け](https://docs.live2d.com/cubism-editor-manual/divide-the-material/)と[イラスト加工](https://docs.live2d.com/cubism-editor-tutorials/psd/)の、観測と描き足しを分ける、動作で露出する範囲を準備する、編集用と出力用を区別する考え方を継続する。Cubismの専用機能や出力形式がInochiでそのまま動くという意味ではない。

| 手法 | 固定Inochi2D 0.8.6での扱い |
|---|---|
| 曲線に沿う細かなメッシュ | Partのmesh/UV、deform bindingで実装する。Cubismのアートメッシュ編集機能を複製したものではない |
| 開閉に沿う遮蔽と線の切り替え | opacity/deform/stencilを使う。raw0を別値へ置換しない |
| 顔/首/体の親子関係 | Nodeの親子transformとPart変形で試作可能。隠れた首/服が用意できるかは別の素材課題 |
| 顔のX/Y/Z | Zの平面傾きは現行HeadTilt。X/Yの見た目には独立した描画状態と補完の検証が必要で、移動パラメータの改名を顔角度の完成としない |
| 髪の遅れ/揺れ戻し | SDKのSimplePhysicsにpendulum/spring_pendulum、gravity/length/frequency/damping等のreaderがある。今回モデルへは未追加、公式実行/時間刻み/保存後の再現を検証してから対応とする |

SDK固定revは`dda3a8f005f808104caa43183ab8753fb989e30f`。根拠は[SimplePhysicsの公開実装](https://github.com/Inochi2D/inochi2d/blob/dda3a8f005f808104caa43183ab8753fb989e30f/source/inochi2d/core/nodes/drivers/simplephysics.d)。これは将来の採用可能性であり、髪の自動物理リギング成功ではない。

## STEP 1：今回の実装範囲

1. 詳細版だけ`contour-lid-v2`を追加し、`detailed-v1`を比較用に残す。既存の5PNG/最小出力は変更しない。
2. 虹彩/白目の下側境界と局所コントラストから下まつ毛を認識。元の取りこぼしと1pxのアンチエイリアス縁を共通データへ移し、RGBAは変更しない。元の半透明画素を不透明な肌へ変えない。
3. 上/閉眼線を同じ25列の輪郭へ変形させる。7段の曲線に沿うmeshを使い、0.075〜0.25では1本の閉眼推定線だけを描く。元の上まつ毛への切り替えはその後に行う。閉眼線の別三角形の羽を連続した1本の多角形にする。
4. 肌の根拠がある観測部分を保持し、目/線を消す必要のある範囲だけ補完。目や髪の色を除外した肌色支持で境界を継続し、近隣肌の微小な塗りの変化を最大RGB±1.25だけ参照する。乱数のノイズや隠れた正解の復元としない。
5. 正確な10開度の独立描画、メッシュの折り返し、元RGBA、残像/穴/線/肌の警告を確認する。公式Creatorでは実際の表示値を照合し、読込/26状態/保存/新プロセス再読込を検証する。

公式GUIの標準パラメータ幅では10回の撮影が9つの値に丸められたため、通常の操作でパラメータ欄を100px広げる。画像・バイナリ・モデルの値は書き換えず、比較前後を同じ配置/実表示値で撮影する。GUIが表示する2桁の値と、独立描画の正確な開度は分けて記録する。

実測と合否は`BLINK_RIG_VALIDATION.md/json`へ保存する。ファイル生成、公式互換、自然な完成品質を別判定にする。

## STEP 2：STEP 1の結果確認後

- HeadX/HeadTiltを保ち、観測した顔/髪/首/胴体と補完領域を共通形式で表す。既存の首周辺連続meshを比較基準に残す。
- 親子構造、首の接続、胴体固定を小さい動作から試す。見えていない首や衣装が支持できなければ、独立レイヤー成功としない。
- 角度X/Y/Zは片軸→組み合わせの順に、原画一致/穴/重複/動作範囲/保存を検証する。2.5Dの平面変形と立体復元を区別する。

## STEP 3：頭部と補完領域の確認後

- 前段の9毛束候補を維持し、髪飾り、手前/奥、根元を改めて評価。曖昧な後ろ髪は確定したリグとしない。
- 根元を支点に小さな手動パラメータ再生で形/穴/重なりを確認した後、自動物理入力へ接続する。「手動パラメータ再生」は開発時の確認操作で、利用者によるリギングではない。
- 無入力/頭部の往復/急停止の時間列で遅れ、オーバーシュート、減衰、初期化、保存/再読込を検証。ブラウザ側の0値/透明度問題はこの生成器へ混ぜない。
