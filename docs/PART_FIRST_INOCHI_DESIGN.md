# 33パーツからのInochi2D自動モデリング

2026-10-24。基準は`feature/part-first-character-generation`の`f107b71`。オーナーが新モードへの実INP/INX出力、独立した左右の瞬き/口/頭部動作、公式Creator 0.8.6での保存・新プロセス再読込を承認した。AI接続/外部送信/課金/main統合/公開は対象外。

## 実装前の整理

- `shared/generated-character.js`の33役割/グループ/元座標/支点/順序/静止meshを入力にする。重なりのある完全なPNGなので、排他的所有を前提とする旧画像分割adapterへ押し込まない。
- 旧`model.mjs`/`character-model.mjs`のlegacyコンテナ、parameter/binding構造、`quality-model.mjs`/`head-rig.mjs`のpremultiplied格納と首の連続変形、詳細版の上まつ毛と開口マスクを分ける考え方を再利用する。正常な旧生成器/worker/APIを変更しない。
- 新しいブラウザ・Node共通の変換を`shared/generated-character-inochi.js`へ分離する。既存の中間ノードを基にPNGを検査し、格納用テクスチャだけ色とalphaを変換する。元の33PNG/manifest/プレビューは不変。
- 対象はテンプレート版1のみ。配置確認用のダミーは解剖的なモデル成功と扱わず、従来どおり静止素材を保存できるようにする。

## 動作

`EyeOpenL/R`は本人左右で0=閉眼/1=開眼。白目を閉眼曲線へ縮め、虹彩/反射は同じ開口でクリップする。上まぶた/まつ毛は厚みを保持して下へ、下まぶたは上へ移動。通常状態の変形は厳密にゼロとする。閉眼時は白目/虹彩/反射を表示せず、元の肌レイヤーを露出する。

`MouthOpen`は0=元の通常口、1=独立した口内。口内の縦変形と表示を設定する。目とは異なるパラメータで制御する。

`HeadX/HeadY/HeadTilt`は小さな平面移動とZ回転。既存のRoot→Body→Neck→Head構造を使用し、顔/耳/目/眉/口/髪はHeadへ追従。胴体/服/肩/袖/襟/リボン/エプロンは固定。首だけ上端から襟まで変形を減衰させる。立体的な顔角度X/Yや髪物理の完成とは扱わない。

## 画面・保存・順序

1. 共通変換と入力検査、最小モデルの生成を追加する。
2. 新モード専用の生成wrapperを追加し、テンプレートの33PNG生成後に自動リギングする。失敗時にモデル成功と表示せず、旧結果を保持する。
3. 素材ZIPに`character.inp`/`character.inx`/実モデルの動作設定/検査レポートを追加。従来の静止素材ZIPも維持し、画面に形式/動作範囲/未検証事項を表示する。
4. CLIは既存ブラウザ生成を再利用し、既存の33PNG+manifestだけからのモデル再生成も用意する。全出力は新規のGit外フォルダ。
5. 実コンテナを既存の独立CPU描画へ渡して通常/左右瞬き/途中/口/頭/複合を比較。公式Creatorで同じ動作、保存、新プロセスの再読込、格納RGBA/mesh/親子/parameter保持を確認する。

ファイル生成、公式での実動作、自然な外見の合否は別記録。Inochi2D旧INP/INX固定で、INP2/Cubism/VTube Studio互換は含めない。Windows/iPhone実機、任意のAI生成画像の一般化も別課題。
