# 生成した肌・目・口から実モデルを作る検証

2026-10-21。オーナーが「今回の画像をOpenAIの画像生成AIへ送り、不足素材を試作する」提案を承認したため実行。作業ブランチは `feature/generated-expression-trial`。前回の [実画像評価](CHARACTER_MODEL_EVALUATION.md) で見つかった、目が閉じない・元の目口が肌に残る問題の改善を目的とする。

## 画像生成と素材の準備

OpenAIの画像生成ツールを3回使用した。有料API契約やアプリからの自動API接続は行っていない。

1. 元のキャラクター画像を参照し、顔の下地、左右の白目・瞳・開眼まつげ・閉眼、開口、閉口、首の候補12個を生成。
2. 初回の白目にまぶた線、開口に唇・歯・舌が混ざったため、連続した白目2個と口内部だけを再生成。
3. 閉眼の線が太く、閉口にハイライトがあったため、細い閉眼2個と閉口線を再生成。外まつげの向きを確認し、出力の左右をキャラクター本人の左右へ割り当て直した。プロンプトの左右指定だけを信用しない。

透過PNGでもalpha0に色データがあるため、実際のalphaを確認した。各部品は等分グリッドからはみ出しており、領域ごとのalphaで切り出した。alpha16以上かつ4連結8画素以上の成分を採用し、保持した画素のRGBAは元シートと一致、alpha0はRGBAすべて0。低alphaの縁も一部除くため、この抽出を元シートの完全保存や最終の輪郭品質とは扱わない。元のシートは保持した。

元の顔・左右の目・口のマスクの和集合を、残す元画像パーツから除去する。元の目の外側159画素は顔ではなくbodyの残りに含まれていたため、顔レイヤーの置換だけでは足りなかった。既知の目口領域の残存0と、除去領域外のRGBA一致を監査する。生成した肌は前髪に隠れる額まで用意し、鼻・顎・元キャンバスに合わせて配置する。元の首輪を新しい肌で覆わないようにする。

画像生成によって、顔・目・肌色の印象は元絵から変わる。部品ができたこと、モデルで動いたこと、元絵への忠実さ、自然さ、VTube Studioでの動作は、それぞれ別に確認する。

## 最新候補v3の結果

元画像からの5パーツと追加11役割を使い、18描画部品/2,430頂点の実MOC3を生成した。テクスチャは2048pxの1枚（展開後16MiB）。元JPEGは変更せず、髪3枚のPNGも元のバイトと一致。bodyに残った元まつげ159画素を除き、可視の元首761画素は元RGBAのまま独立した首パーツへ再割当した。初候補の生成neckはこの版では使っていない。

## 今回のコード改善

### 元位置を保った透明余白の削減

モデル用PSDの各レイヤーをalpha>0の範囲へ切り詰め、`left/top`に元位置を保持する。合成と重複チェックは切り詰める前の元キャンバスで行う。元PNG/作業ZIPを書き換えず、alpha1や半透明画素も落とさない。完全透明の素材は生成前に明示的に拒否する。

自作5素材の実MOC3比較では、テクスチャが1024pxを5枚から1枚へ減少（20MiB→4MiB）。7部品のIDと配置を保持し、独立ランタイムで初期位置の最大差は約5.96e-8、各サンプルは有限値だった。この80%削減をすべての画像やスマホの総メモリ量へ一般化しない。

### 閉口時に開口が残る候補の検査

独立ランタイム検証へ、認識できる口部品の透明度を最小/25/50/75%/最大で追加した。最大64部品、ID最大128bytes。標準パラメーターや認識IDがない場合は診断を利用不能とし、カスタムモデルの構造検証を拒否しない。

口を閉じた値で閉口部品と開口部品の透明度がともに正の場合、`mouthVisibility`に候補を記録し、生成後の画面へ二重表示の確認を促す。透明度は表示フラグやクリッピングの影響を含まないため、表示不良の確定判定ではない。

psd2liveの固定元SHA `2db3307373c9b7df69ca9a51aae9135ba52d131a` で、閉口用の分類を開口の消去判定に含めていない問題を実物で確認した。**外部ツールのローカル検証用コピー**の検出を修正し、閉口ありの自作モデルでは開口/自動唇の透明度が閉口時1→0、開口時1、閉口線はその逆になった。閉口素材なしの自作モデルは修正前後のMOC3バイトと100サンプルの形状/透明度が一致。アプリのGitに外部GPLソースや修正パッチを同梱したものではない。

当該`RigBuilder.kt`のSHA256は修正前`32ec14bce4aae593ce0e4b1d92f3fb1ebdd32cec19f0b0e9d13ff9678a6c502b`、口検出だけを修正した時点で`75b8f22d50d5dadddf2012f3b4318e3134fb1e04872097ccc69ce3d74fa2a857`。後続の閉眼調整は別途記録する。未修正版の外部ツールを新環境で使うと、同じ問題が出る可能性がある。アプリの診断で候補を残し、初期モデル生成の成功を表情品質の成功としない。

閉眼差分がある側だけ、開度0〜.15で白目/瞳/開眼まつげと閉眼線の透明度を相補に切り替えるローカル調整も実施した。0で前者0・閉眼線1、.15以上では前者1・閉眼線0。半開きに別の閉眼線を重ねず、閉眼時の青い残りを除く。閉眼差分なしの自作モデルは口修正時点を基準にMOC3バイト/100状態が一致。差分ありでは全開は一致し、他の状態に最大約2.09e-6の座標差があるため、完全一致とはしない。UV/インデックス/マスク/順序/色は一致。最終`RigBuilder.kt` SHA256は`d19c1b1be6c830ae4ff22e25ed868eece9794f651a14acdefab2937fe830ff66`。この外部ツール調整のソース/パッチ/バイナリもアプリへ同梱していない。

### 閉・途中・開の実描画比較

`render-preview.py --poses expressions`で、通常、左右別の閉/半開、両目の閉/半開、口の半開/開、両目閉+口開の10状態を共通範囲・倍率で描画する。引数なしの従来7状態は維持。レポートへ`pose_set`と適用値/欠落IDを記録する。

```bash
python3 scripts/model-build/render-preview.py \
  --library /path/to/libPurismCore.so \
  --model /path/to/character.model3.json \
  --output /tmp/new-expression-preview \
  --poses expressions --height 512
```

独立実装による最近傍診断で、公式CoreやVTube Studioの検証ではない。閉眼時は瞳の部品を一時的に消した描画とも比較し、見た目で分かりにくい青色の残りを検査する。

### 保存して開く表情確認ページ

描画済みPNGと任意の作業/モデルZIPを、単一HTMLへまとめられる。10状態の選択/自動切替、顔/全身、白/黒/市松背景、同梱ZIPの保存に対応。Live2Dのリアルタイム描画や追跡ではなく、実モデルから描画した状態の比較ページである。

```bash
node scripts/model-build/create-preview-page.mjs \
  /tmp/new-expression-preview /tmp/new-character-review.html \
  --work /path/to/character-work.zip --model /path/to/character-model.zip
```

画像を含むためGitの外の新しいファイルだけへ保存する。Gitへ向く親ディレクトリのシンボリックリンクも拒否。PNG/ZIPの容量は読み込み前に残り予算で制限し、総入力48MiB以内。画像/ZIPを埋め込み、外部フォント/API/画像URLは使用しない。

今回の`trial-v3/character-preview.html`は約9.4MB。クラウドChromiumの管理設定で`file://`は拒否されたため、その設定を変更せず、同じHTMLを一時的なループバックHTTP配信で検査した。10状態/選択/再生/320px縦画面と横画面/48px操作/外部通信0/画面エラー0、HTMLから保存した両ZIPの元ファイルとのバイト一致、上書き/容量超過拒否を確認。Windowsでファイルを直接開く実機検証はまだ行っていない。利用者はHTMLを端末へ保存してブラウザで開く方式で、クラウドのlocalhostをWindows用URLとして案内しない。

### 髪を手前に戻して配置確認

表情合成の「背景」に **元画像＋分離した髪（位置確認）** を追加。元画像→追加素材→AIの前髪/横髪を重ね、顔下地が前髪を覆う状態を確認しやすくする。制作向け髪があれば基本の髪より優先し、後ろ髪/デモ/異寸法は除外する。

既定は従来の透明背景。髪は最大640×960の縮小キャッシュ1枚で保持し、各PNGを順次読み込み、古い読込やリセット後の結果は描画しない。選択は表示用で、素材/配置/作業形式/確認メモは変更しない。メイン合成だけの静止した位置確認で、詳細/比較/編集下書きには髪を重ねない。モデルと同じ動きや髪の欠けの補完は保証しない。

## 保存と再開

元画像・生成シート・切り出し・PSD・モデル・比較画像はGitへ含めない。画像生成ツールの原出力はGit外の`/workspace/generated_images/`、評価用コピーと出力は`/tmp/ai-live2d-generated-trial/`。手作業の位置合わせや実行した外部ツールの識別は、この私用フォルダーの`trial-provenance.json`等に残す。クラウド環境終了後の画像・外部ツール・プロセスの保持は保証しない。

コード/画像なしの検証記録は作業ブランチへ保存する。利用者が端末に保存した作業ZIPで元画像と素材配置を再開でき、モデルZIPは作業再開には使わない。今回の生成素材準備は開発時の検証であり、アプリ内で画像1枚から完全自動生成するAPIは未実装。外部サービスの追加、有料契約/課金、main統合/公開は引き続き別の判断とする。
