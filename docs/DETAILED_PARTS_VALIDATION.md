## 人の制作手順から採用したこと

Live2D公式の公開本文から、元絵をマスクで残す、描き足しを別レイヤーにする、動くと露出する範囲を準備する、編集用と出力用を区別する考え方を採用。具体的な色・形の分類器や数値は本プロジェクトの設計で、公式が提供する自動分割方法ではない。

Palmieの2ページとお絵かき図鑑は接続403で本文未取得。読めた資料として扱っていない。有料講座、動画、PSD、サンプルモデルは取得していない。出典と取得状況は上記の設計資料へ記録した。

## 共通パーツと目の分離

`shared/character-parts.schema.json`と`server/character_parts.py`へ、Inochi2Dノード番号に依存しない版1を追加。役割ID、本人基準の左右、元画像の整数座標と正規化配置、観測RGBA/mask、重なり順、親子、被覆するパーツ、補完RGBA/mask、推定根拠、動作範囲を記録する。

元画素は1パーツだけが所有。認識が不確かな画素は`context`や残余前景へ残し、補完を中立状態へ自動合成しない。欠けた瞳孔・ハイライトは`missing/ambiguous`としてPNGなしで記録し、透明なダミーで代替しない。確信度は未校正の目安で、正解確率ではない。

今回の共通データは36パーツ、RGBA/mask合計98PNG、展開量約23.86MiB。左右は本人基準（`l`が画面右）。両目に次の観測パーツを保存した。

| 役割 | 本人の左：画素数 | 本人の右：画素数 |
|---|---:|---:|
| 上まぶた | 1,083 | 1,062 |
| 下まぶた | 531 | 766 |
| 上まつ毛 | 1,480 | 1,577 |
| 下まつ毛 | 16 | 13 |
| 白目 | 739 | 899 |

| 瞳孔 | 267 | 286 |
| ハイライト | 81 | 56 |

白い反射と白目は虹彩内外で区別。虹彩の色相は入力から測り、紫固定にしない。自作の紫・緑・茶・赤の目で既知の画素ラベルを確認した。ただし実画像は1枚で、一般的な成功率や認識精度はまだ算出できない。下まつ毛は観測数が小さく、線の一部がcontextに残る。

## 隠れ部分の補完

- 目の下の肌：前段の局所肌推定を14,553画素の別レイヤーにした。元の肌を書き換えず、由来を識別できる。
- 虹彩の後ろの白目：左右2,572/2,606画素。見える白目の縦方向の色・陰影から推定。
- 瞳孔/反射の後ろの虹彩：左右348/342画素。虹彩の可視領域だけを参照する局所補間。
- 前髪の奥の肌：見える肌から3px以内の3,543画素だけを継続。額全体の復元ではない。
- 毛束の根元/被覆境界：その毛束自身の可視色を最寄り参照し、最大2〜6pxの範囲だけ継続。今回の画像では5px。別の毛束の塗りをコピーしない。

補完前後の比較PNGを出力する。これらは局所推定で、隠れた形状や画風の正解を復元したという判定ではない。虹彩/白目/髪の補完は共通編集データに保存し、現在の瞬き出力で独立した視線・髪の動きへはまだ使っていない。

## 髪の候補と失敗

SAMへ顔検出から自動計算した点/枠を渡し、画像の長い輪郭を境界にwatershedで候補を分割。利用者の点指定や等間隔の帯分割ではない。最終的に毛束9候補、155,355画素（SAM髪候補の56.17%）、残る121,221画素は前/左右/後の粗い領域として保持した。前後関係はすべて未検証で、位置だけによる後ろ髪判定を確定しない。

初回は暗いカチューシャの6,436画素まで10番目の毛束と誤認した。疎で細く、周囲の髪色と大きく異なる領域を保留する処理を追加し、元画素を粗い領域に戻した。黒髪そのものを暗いという理由だけで拒否しない回帰を追加した。別色の髪が保留される可能性もあり、これはアクセサリー認識の完成ではない。

独立した揺れ、確かな根元/奥行き、広い隠れた髪は未実装。細いテクスチャ継続に乱れもあり、そのまま完成した髪素材としない。

## 瞬きの改善と自動品質検査

共通データからの`parts-adapter.mjs`だけで、上まつ毛の暗い線を中心位置で閉眼線へ合わせ、厚みを計測して圧縮。下まつ毛は別ノードにし、早めに消して閉眼位置へ寄せた。白目/虹彩/瞳孔/反射/まぶたの肌/contextは、**現在の4パラメータ出力時だけ目全体の画像へまとめる**。元の編集用PNGは独立したままで、視線や瞳孔の独立リグが完成したとはしない。

11描画ノード（うち開口mask2）、10テクスチャ、1,405頂点、2,416三角形。`EyeOpenL/R`、`HeadX`、`HeadTilt`。前段の首周辺meshと胴体固定、±12px/±.045radの動作量は維持した。モデルのRGBは公式0.8.6が読むpremultiplied形式、共通PNGは元のstraight RGBAを保つ。

独立CPU描画器で実際のINP内のmesh/変形/opacity/stencilを評価し、開度0/.025/.05/.075/.1/.15/.25/.5/.75/1を検査。公式ランタイムの代用の合格判定ではなく、不具合候補を見つける補助とする。

| 指標 | 改善前cd4c2b7 | 今回 | 解釈 |
|---|---:|---:|---|
| 10状態の目元の透明穴 | 0 | 0 | 元の目があった対象領域のみ |
| 完全閉眼の目画像寄与/虹彩色候補 | 0 / 0 | 0 / 0 | raw0で目画像なし。寄与は目全体maskによる上限で、意味ごとの虹彩画素追跡ではない |
| 開度.025の線の中央値 | 5px | 4px | 単純な列方向の線量。自然さの点数ではない |
| 開度.05の線の中央値 | 9px | 4px | 閉じ際の太い帯を削減 |
| 開度.05の二重線候補列 | 9 | 1 | この状態では減少 |
| 開度.075/.1/.15/.25の二重線候補列 | 10/9/10/10 | 16/21/25/27 | **増加。未解決警告として保存**。外側の元まつ毛も検出し得るが、解消済みとしない |
| 補完肌/近隣肌の細部量比 | — | .00421 | 平滑化の警告あり。隠れた肌の正解画像はない |

虹彩中心の列に限った線検査は前後とも0だが、全体の警告を上書きしない。肌のぼけは検出を追加した段階で、改善したとは判定しない。故意の穴・虹彩色残像・二重線・平滑化を与えた自作例で、検出器が反応することも確認した。

## 公式Creatorと比較画像

Linux版Creator0.8.6をXvfb/Mesaで実行。公式バイナリSHAは`2ae3b449a8bd32c826d851a5663e58f3df451b0cfbbed0aa64121ce1f1eb9bcc`。SDK固定版はv0.8.6 `dda3a8f005f808104caa43183ab8753fb989e30f`。INP2やWindows/スマホ実機の確認ではない。

- 両目/片目の閉眼・途中・開眼、頭の左右と傾き/独立操作、複合/復帰、低開度を含む26状態を操作。
- 実際のGUI表示値を照合。途中は.48、低開度10撮影の表示は0/.03/.06/.06/.10/.16/.26/.48/.74/1。10回のうちユニーク値は9種で、正確な.025/.05等のGUI撮影と呼ばない。
- 保存し、別のプロセスでINXを開き直して同じ26状態を再操作。全viewportの画素差0、胴体の固定領域も全状態で差0。
- 保存されたTGAと生成時PNGをノードごとに比較し、11ノード/10テクスチャの格納RGBA、mesh点数、4パラメータ名を保持。

私用成果物は`/tmp/inochi-parts-trial`。`comparison/12-state-before-after.png`と`closed-half-before-after.png`は公式Creatorの前後比較、`10-blink-states.png`は公式の途中撮影。`low-opening-before-after.png`は独立CPU診断。`source-reconstruction.png`は元絵/抽出前景/共通データ再構成/差分。`failure-examples.png`は初回の髪飾り誤認と残る肌/線の問題。分割・補完・髪の比較は`delivery/`にある。

`comparison/review.html`は画像切替のオフライン比較で、ブラウザ上のInochi実行ではない。390×844のChromiumで12状態の切替、48pxの操作領域、16pxの文字、横はみ出しなし、外部要求なしを確認した。

node --test scripts/inochi2d/*test.mjs scripts/model-build/*test.mjs

Node52、Python59、既存ブラウザ140の**計251件成功**、本番build成功。Pythonには既存Starlette/httpxの非推奨警告1件。自作例/検出差替え/通信代替を含むテストと、実画像の無操作生成/公式GUIの実証は別に扱う。誤って`unittest`で起動した確認は0件だったため成功件数に数えず、pytestで全件実行した。

通常の`inochi_preparation.py`/worker/API/UI、既存`model.mjs`/`generate.mjs`/`quality-model.mjs`/`character-model.mjs`は変更していない。旧5役割manifestから再生成したSHAも`dfc65b5dbb9c7e99852d6e7b710bb9b72f600d72cf871a0fe020660d04d327e9`のまま。通常アプリのボタンがこの詳細CLIへ切り替わったわけではない。
