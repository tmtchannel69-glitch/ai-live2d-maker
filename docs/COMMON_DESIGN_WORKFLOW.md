# 共通デザイン原画から髪を揃える

現在の優先は、同じ原画に基づく**前髪・横髪・後ろ髪の画風と形を揃えること**。横髪は本人の左右で別PNGなので、3系統で4ファイルになる。既存33パーツ・交換・Inochi2D出力・画像1枚からの変換は維持する。AImyの独自素材は使用しない。

この実装は、ChatGPT等で作った素材を**手動でファイル選択し、配置・モデル化は既存の処理で行う**工程。AIへの送信・画像生成APIはない。原画を登録しても、自動でパーツ画像が増えたり既存キャラクターの絵が描き替わったりはしない。

## アプリでの順番

1. 「キャラクター制作」でベースを用意、または前回の制作ZIPを再開する。
2. 「共通原画からデザインを揃える」を開く。自分が使用できる完成キャラクター画像を選び、「原画と共通条件を登録」。選択だけでは画像を読み込まない。PNG/JPEG/WebP、8 MiB、各辺64〜4096px、800万画素以内。空・ほぼ透明・単色画像は拒否するが、人物の検出や高品質判定はしていない。
3. 名前、任意の線幅（基準768×1024上）、髪色最大5色、陰影、光源を共通条件にする。未指定の項目は「原画に合わせる」であり、自動で画風を認識した結果ではない。
4. 「原画・髪の制作依頼と33パーツ仕様を保存」。同じ原画とガイドをChatGPTの各生成で参照する。出力された前髪・左右横髪・後ろ髪を、独立RGBA8 PNGで用意する。役割名は下表の通り。
5. PNG複数、または既存の部品ZIPを選ぶ。「同じ原画を参照して作った素材です」にチェックして「検査して交換」。これは**利用者の申告**で、生成元の認証ではない。ファイルや原画/条件を変えるとチェックを解除する。
6. 原画と組み立ての左右比較、髪4枚、動作を確認する。1枚から取り込めるが、未関連付け・旧原画・未提供の素材を不足として表示する。4/4になっても完成品質は未確認のまま。
7. 制作を再開したい場合は「制作ZIPを保存」。原画・比較PNG・髪・検査だけ欲しい場合は、別の「原画・髪4枚・比較画像・検査ZIPを保存」を使う。

| 系統 | 役割 / ファイル |
| --- | --- |
| 前髪 | `bangs_front.png` |
| 横髪 | `side_hair_l.png` / `side_hair_r.png` |
| 後ろ髪 | `back_hair.png` |

左右はキャラクター本人基準。本人左は画面右。横髪を1枚に合成しない。

## 生成・検証の共通仕様

`part_contract.json` は原画の元ファイルとSHA256、共通条件とそのSHA256、33役割のrect/anchor/parent/order/clipを記録する。PNGのalphaをマスクとして扱い、隠れ領域は要請・未検証として明示する。**Inochi2Dとは独立した配置仕様**で、Cubism/MOC3対応を表すものではない。

`chatgpt_hair_instructions.txt` は以下を具体的に指示する。アプリがこの文章や画像を送信することはない。

- 全パーツに同じ原画、線、色、陰影、光源を使う。別々のキャラクターとして生成しない。
- `rect.width × rect.height` の切り抜きPNG、または可視画素がrect内に限られる768×1024配置済みPNG。画像の縦横を別々に伸ばさない。
- 前髪に顔や瞳を描き込まず、横髪は左右別にする。後ろ髪は顔/首/胴体の背後の下地も描く。支点と毛先を切らない。
- 顔・目・衣装も同じ仕様で後続にする。目の白目/虹彩/反射/上下まぶた/まつ毛/眉は独立PNGのままにする。

任意サイズの前髪は、既存の等比配置と目・眉の被覆検査を再利用する。他3枚は現行ガイドの寸法・座標を使う。前髪以外の配置枠の自由拡張、原画からの人体位置推定は今回実装していない。

原画の表示は縦横比を保つcontain配置。**原画の目・顔・髪と、テンプレートの解剖的位置の一致は未確認**。ガイドにはこの制約を明記する。元のJPEG/PNG/WebPは全バイト保持し、表示用比較画像とは分ける。

## 自動検査で分かる範囲

| 項目 | 実装した観測 | 合格としないこと |
| --- | --- | --- |
| 座標・構造 | 従来の厳密な33役割、寸法、支点、親、順序、首/目検査 | 任意の原画の解剖的位置を正しく推定したこと |
| 透過 | alphaの可視bounds、薄い残留、強い画素の画像端接触 | 背景や毛先を意味で認識し、完全に消せたこと |
| 色 | 上位色とLab ΔE76、任意の指定髪色との比較、髪同士の比較 | 色差が小さいため画風も一致するという判定 |
| 線 | 短い暗色線の縦横runの中央値（代理値） | 作者の正確な線幅、輪郭線の意味、黒髪/黒衣装の線の認識 |
| 陰影 | 明るい素材画素の輝度ばらつきと比 | 光源方向、セル塗り/厚塗りの意味的認識 |
| 隠れ領域 | 支点周囲17px角の不透明率、宣言された被覆パーツの下で基準不透明画素を2px間隔で調べる | 隠れた根元/肌の正しい形、描き込み、自然な動きの保証 |

代理値が測れない箇所はnull/不明とする。画像を描き替えたり閾値を変えて合格を作らない。数値の注意がなくても`appearance_quality_passed`、`style_consistency_verified`、`hidden_surfaces_verified`はfalse。保存済みの有利な検査JSONも信用せず、再開時に実PNGから再計算する。

原画SHAまたは共通条件SHAが変わると、以前のパーツを旧条件として表示する。通常の交換で由来情報を消した場合も未関連付けとなる。取り消しで該当PNGと由来を復帰できる。素材同士の絵柄の不一致を、ファイルの指紋だけで解決した扱いにはしない。

## 保存と旧版

| 対象 | 形式 |
| --- | --- |
| 原画なしの制作 | 従来のmaker_project v1/v2、PNG/INP/INXを維持 |
| 原画を含む制作 | maker_project v3。`design_reference`、元の`design/reference.png/jpg/webp`、`design/contract.json`、`design/quality.json`を追加 |
| 部品の関連付け | user-pngのoriginに`design_binding`（原画SHA、条件SHA、自己申告、AI認証false） |
| 制作ガイド | 元原画、配置ガイド、33仕様、髪生成依頼、READMEの5項目 |
| 確認ZIP | 上記＋作業中プレビュー、左右比較、髪4枚の比較、個別4PNG、検査JSONの13項目 |

制作ZIPは圧縮/展開48 MiB・128項目、確認/ガイドZIPは展開24 MiB。原画8 MiB、部品ZIP16 MiB、現在PNG合計12 MiBという上限を保つ。失敗/中止で前の制作を置き換えない。原画入りv3は以前のアプリでは開けないので、このブランチを更新する。

原画の登録や比較ではモデルのPNG・メッシュ・共通7制御を変えない。モデルはInochi2D legacy0.8.6。画像1枚からの5パーツ/詳細経路、従来の33パーツ生成器は変更しない。

## iPhoneでの確認・保存

原画/組み立て/左右比較/髪4枚をタップすると拡大する。2倍の表示とスクロールができる。「画像を共有・保存」は、準備済みの実Blobをタップ直後にWeb Shareへ渡す。対応するSafari/HTTPSなどでは共有先から「ファイルに保存」を選べる。未対応時はダウンロードへ切り替え、「画像だけを開く」も使える。共有の取り消しは失敗や保存完了にしない。

この導線はChromiumの320/390pxタッチ設定と共有処理の模擬で検証する。**実iPhone/Safari、ファイルアプリの保存は未検証**。Codexクラウドの/tmpやlocalhostは端末のダウンロードURLではない。今回も回答へZIPを添付/認証URLを発行する手段はなく、クラウド成果物のiPhoneへの受け渡し完了は主張しない。外部Drive送信/アプリ公開もしていない。

## 実画像で再現する

Node/依存を既存手順で準備し、ローカルアプリを起動する。重みや画像APIは不要。

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

別ターミナルで、本人が持つ2枚を指定する。未作成のGit外ディレクトリを出力先にする。スクリプトは既存の出力を上書きせず、画像がなければ失敗し代替素材を使わない。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node scripts/character-maker/reference-design-trial.mjs --reference /path/to/owner-portrait.jpg --bangs /path/to/owner-bangs.png --output /tmp/NEW-common-design --url http://127.0.0.1:5173
```

`--expected-reference-sha` / `--expected-bangs-sha` で入力を固定できる。Windowsでは環境変数を実在するChromeに設定し、パスを置き換える。スクリプトによるブラウザ自動取得は行わない。

この試験は、既提供画像を仮原画として登録し、前髪を既存の自動配置で装着し、実データ保持/全33枚・native不変/7操作/ZIP/再開/外部通信0を確認する。**元の前髪がこの仮原画を参照して生成されたとは確認できないので関連付けの申告をせず、髪セット0/4を維持する**。一致する横髪や後ろ髪があると偽らない。

実測と残課題は[検証記録](COMMON_DESIGN_VALIDATION.md)へ。

## コード

- `shared/design-reference.js`：共通条件/原画/関連付けの形式、画像ヘッダーと上限。
- `shared/design-part-quality.js`：色/線/陰影/alphaの観測。画像の再生成・自然さ合格は行わない。
- `src/character-maker/design-workflow.js`：原画の元データ保持、33仕様、髪の一括交換、原画比較、下地候補。
- `design-review.js`：ガイド・依頼文・左右/髪比較・ZIP。
- `design-panel.js` / `mobile-image-save.js`：スマホ確認とタップ時の画像共有/保存。
- 既存 `project.js` / 生成器 / native writerは変更せず、`archive.js`・`panel.js`・`guide.js`の追加経路で接続。

次は、確定した同じ原画で生成した実際の髪4枚を用意し、根元・毛束・線と光・顔への接続を目視確認する。その後、顔・目・服にも同じ原画の取り込みを広げる。API接続は別承認で、今回の送信/課金は0。
